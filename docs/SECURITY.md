# 安全与隐私

用户最在意的就是安全。任何改动如果涉及以下内容，先读本文件，并在改之前向用户说明风险。

## 已知局限（要对用户诚实）

- 打码规则抓不住所有隐私（例如窗口标题里的聊天对象名字、文档名）。主要防线是「黑名单」和「只发摘要」。
- 「像密码」规则认不出 `zhang123456`、`password1` 这种只有一处字母→数字切换的弱密码（和 `Windows11` 长得一样）；反过来会误隐藏少数正常串（YouTube 视频编号、UUID、提交哈希、`Q&A_2024` 这类带符号的名字）。
- 摘要会发给所选的大模型服务（DeepSeek 或订阅制 Agent 的厂商）。建议用户在各家设置里关闭「用于训练」。
- 陪伴文件夹里的 `.mcp.json` 含只读钥匙（明文）。只读钥匙改不了记忆，但能读记忆；该文件夹只在本机。
- 程序没有代码签名，杀毒软件可能误报。

## 新增采集来源的检查清单

1. 是否真的需要？能不能用更少的权限达到目的？
2. 落盘前是否经过黑名单和打码？
3. 原始数据是否只在本机、有保留期限？
4. 交给 AI 的是否只是摘要？
5. 是否在 VISION.md「明确不做」的清单里？在的话必须先和用户确认。
