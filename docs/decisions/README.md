# 设计决定记录

每个重要决定一节：当时的情况、选了什么、为什么、放弃了什么。想推翻某个决定，先读它，再和用户商量，然后在这里追加新的一节（不要删旧的）。

## 0001 自己实现记忆库，不直接用 Graphiti（2026-11-20）

- **情况**：用户喜欢 Graphiti 的「事实带有效期」，并要求打包成点开即用的 exe。
- **决定**：借鉴 Graphiti 的数据模型和判断规则，用 SQLite 单文件自己实现。
- **原因**：Graphiti 依赖 Neo4j 等需要单独安装运行的图数据库，难以打进 exe；它的大模型调用写死在内部，和 DeepSeek 的兼容性没有保证。
- **放弃**：Graphiti 的社区聚类、多跳图遍历（个人数据量下用处不大）。

## 0002 记忆库内部不调用大模型（2026-11-20）

- **决定**：存储和检索是纯代码；「判断」交给外部整理者（DeepSeek API 或订阅制 Agent），通过工具调用写入。
- **原因**：订阅制 Agent 只能在自己的官方客户端里用，不能把账号接进第三方程序；把智能放在外面，订阅和 API 都能用。检索也更快、免费、可预测。

## 0003 读写分开，两把钥匙（2026-11-20）

- **决定**：只读入口（读 + 留便条）给聊天的 AI；整理入口（全部写入）只给定时整理任务。
- **原因**：用户要求；防止聊天时被网页内容诱导的 AI 改写记忆。

## 0004 用文件夹区分工作模式和陪伴模式（2026-11-20）

- **决定**：只有陪伴文件夹有项目级 MCP 配置；不在任何全局配置里接入记忆库。
- **原因**：用户工作时不希望加载记忆（耗额度、干扰工作）。只在说明文件里写「工作时别用」不可靠，工具定义本身也占 token。

## 0005 只用一个大向量模型 bge-m3（2026-11-20）

- **决定**：只支持 BAAI/bge-m3 官方 ONNX（约 2.3GB），用 ONNX Runtime 在 CPU 上跑。
- **原因**：用户决定。切换模型要重建全部索引，不如一步到位。没有独显也能用（每天计算量很小）；不用 PyTorch 以控制体积。
- **放弃**：小模型 bge-small-zh。

## 0006 桌面程序用 PySide6，安装包用 Inno Setup（2026-11-20）

- **决定**：界面 PySide6（Qt），PyInstaller 打包为文件夹形式，Inno Setup 生成安装/卸载程序。
- **原因**：用户要桌面客户端（不要网页）、托盘、必须有卸载程序。全项目只用 Python 一种语言，方便多个 AI 接手。
- **放弃**：Tauri（要学 Rust）、Electron（体积大）、网页界面。

## 0008 聊天只在本程序里；订阅制 Agent 由本程序通过 ACP 调用（2026-11-20，取代 0004）

- **情况**：一开始的设计是把记忆库写进各家 Agent 的配置（陪伴文件夹 / 全局配置 + 陪伴模式开关），用户在别家软件里聊天。
  实际试用中：Antigravity 只认全局配置，用户拖 JSON 时被写进了全局；改别家配置还要备份、怕无限备份；用户也不希望工作时被记忆打扰。
- **决定**：聊天只在本程序的「陪我聊聊」里进行。「由谁来回答」可选 DeepSeek API 或订阅制 Agent；
  订阅制的由本程序启动它的官方命令行（如 `agy acp`），用 **ACP（Agent Client Protocol）** 在 `session/new` 里临时传入记忆库 MCP。
  Agent 每次调用工具都会发 `session/request_permission`，本程序只放行记忆库自己的工具，其余一律拒绝。
- **原因**：不改任何别家软件的配置（没有备份问题）；用户自己打开那些软件时完全看不到记忆；每次工具调用都过本程序这一关，更安全；
  ACP 是通用标准，Claude Code、Codex 也有 ACP 接入方式。
- **实测**（2026-11-20，Antigravity CLI 1.5.13）：`session/new` 带 `mcpServers:[{type:"http",name,url,headers:[{name,value}]}]` 成功；
  模型调用 `mcp_<name>_get_user_context` 前发来权限请求，放行后正确读到测试记忆。一轮约 1.3 万输入 token（8 千缓存命中）。
- **注意**：分享给别人时，订阅制 Agent 必须用对方自己的账号；各家条款开工时逐一核对。

## 0007 不用无障碍、不录音、不读通知（2026-11-20）

- **决定**：采集只用不需要危险权限的来源。
- **原因**：用户非常在意安全：无障碍能读到一切，是诈骗软件常用手段；录音耗电且录到别人；通知里有验证码。

## 0009 中英双语，中文原文当键（2026-11-20）

- **情况**：用户希望 GitHub 上其他国家的人也能用，先做简体中文 + English。
- **决定**：中文是原文，其他语言各一个 `ui/i18n/<代码>.json`（键 = 中文原文），界面（`T()`）和后台（`t()`）共用同一份。
  默认「跟随系统」：Windows 界面是中文就显示中文，否则英文；用户可在左下角地球图标或设置里切换，存在 config.json 的 `language`。
- **原因**：维护的人（和 AI）读代码时直接看到中文原文，不用来回查键名；漏翻时退回中文，不会崩。
  加语言只需多一个 JSON 文件和两行登记。
- **范围**：只翻译给人看的（界面、接口提示、托盘、通知、安装包、说明书）。写给 AI 的提示词、工具说明保持中文；
  整理任务里会告诉 AI 用当前语言写新记忆，聊天时 AI 用用户说话的语言回答。已存下的记忆和原始记录不翻译
  （「[隐私窗口]」「[已隐藏]」在显示时翻译）。

## 0010 程序内检查更新：单独的公开发布仓库（2026-11-20）

- **情况**：用户调试时每次都要卸载、重装；希望点「检查更新」就能升级。源码仓库是私有的，别人的电脑读不到。
- **决定**：新建公开仓库 `The-Dark-Iceberg/always-with-you-releases`，只放安装包和更新说明，源码暂不公开（用户以后再决定）。
  每个版本发成 GitHub Pre-release，标题和说明都写明「测试版」；仓库 README 说明这是测试仓库（模板在 packaging/releases-repo/README.md）。
  发布用 `packaging/release.ps1`，**每次发布前要用户同意**。
- **安全**：只在用户点按钮时联网；只认写死的仓库、GitHub 域名、固定文件名；必须核对 SHA-256 才安装；每次都要用户点「是」。
  静默覆盖安装（/SILENT），不运行卸载程序，所以数据不受影响；装完由安装包把程序重新打开（installer.iss 的 Check: WizardSilent）。
- **以后**：正式版前考虑代码签名，防止发布仓库账号被盗时被换成恶意安装包。


## 0011 更丰富的采集、聊天参与整理、说话人权重、时区（2026-11-20）

- **情况**：用户指出只记窗口标题「像个大号进程监视器」；聊天内容没进记忆；留学生电脑时区和生活时区可能不同。
- **采集新增**（都不用无障碍、不截图、不读键盘）：
  - **正在播放**：Windows 系统媒体接口（SMTC，就是音量浮窗里显示歌名的那个），后台播放也能拿到歌名 / 视频标题。
    听歌看视频**不走「不记录的软件」黑名单**（用户：这些不是隐私），只过密码类打码。无痕窗口里放的视频也会被记到，只在说明里提醒。
  - **最近打开的文件**：Windows「最近使用」文件夹里的快捷方式名，只记文件名，不读内容，过隐私规则。
  - **浏览器扩展**（Chrome / Edge）：只记当前标签页的**网址（去掉全部参数）、域名、标题**，以及常见搜索引擎的**搜索词**（先提取再去参数）。
    **只记 https**，http 页面一点都不记。不读网页内容和输入框。扩展随安装包带，用户点「安装浏览器扩展」确认后复制到自选文件夹，
    再自己去浏览器「加载已解压的扩展」。不从 GitHub 拉。
  - 不做：活跃程度（打字检测）、Wi-Fi 位置、截图。
- **聊天参与整理**：每个整理时间段，把这段时间的聊天（用户和 AI 双方）作为一份 episode 和电脑活动摘要一起整理。
- **说话人权重**（GitHub 上没有现成的分级算法：Mem0 旧版只看用户、Graphiti 只标说话人不降权，所以自己设计）：
  - 每条事实记 `speaker` 和 `confidence`：note（「记住……」）1.0、user（用户说的）0.9、user_agreed（AI 说、用户认同）0.8、
    shared（一起聊过的事）1.0、pc（电脑活动推测）0.6、assistant（AI 说、用户没接话）0.4；用户否认的不记。
  - 检索得分多乘 `0.6 + 0.4 × 可信度`。
  - 加强分：用户再提 +2、电脑活动 / 认同 / 聊过 +1、**AI 复述 +0**（防止 AI 把记忆复述一遍就越记越牢）。
  - 推翻：说话人等级低的不能推翻等级高的（note > user = user_agreed = shared > pc > assistant）。
  - 用户亲口说了 AI 之前猜过的事：可信度提升到用户那一级。
- **时区**：设置「我所在的地区」，默认跟随电脑。用电脑时钟的 UTC 时间换算成所选地区（含夏令时），
  整理时间、「今天」、记忆里的时间都按它算。不联网查位置。依赖 tzdata（Windows 版 Python 不带时区库），随安装包打包。

## 0012 联网、便条核对、电脑睡眠、首次打开、记忆库搬家与导出（2026-11-21）

- **联网（所有 Agent 通用）**：陪伴说明里去掉「不要上网」。按 ACP 工具「类别」统一放行，不针对某一家：
  记忆库工具、`search`（上网搜索）、`fetch`（读网页）、`think` 放行；`read / edit / delete / move / execute` 和不认识的一律拒绝。
  读网页时网址是本机 / 局域网（localhost、127.x、10.x、192.168.x、无点的主机名、.local 等）的也拒绝。
  聊天气泡上显示搜了什么词、开了哪个网站。DeepSeek 不管（它没有上网工具）。
  实测（2026-11-21）：Antigravity 的 ACP 模式没有单独的「读网页」工具，要看某个网页时用带 domain 的搜索；
  它试过用 PowerShell 下载网页（execute），会被拒绝。
- **「记住」便条必须是用户本人说的**：AI 留 remember / correct 便条时，程序看用户刚说的那句话里有没有
  「记住 / 别忘了 / 你记错了 / 不对 / 其实……」这类词（ops.REMEMBER_WORDS / CORRECT_WORDS），没有就降成普通便条；
  便条里自动附上用户原话，整理规则要求先核对原话。只看关键词，不靠 AI 判断。
- **电脑睡眠**（统一叫「电脑睡眠」，笔记本台式机、各品牌通用，只用 Windows 自带的东西）：
  - 主：采集线程每 5 秒醒一次，睡眠时整个程序被冻住（实测睡眠期间一条记录都没有），醒来发现间隔超过 1 分钟就是睡过。
  - 校准：用 `wevtutil` 读「系统」日志里的电源事件（Kernel-Power 42/506 进入、107/507 退出、Power-Troubleshooter 1 恢复），
    把开始 / 结束校准到准确时刻。读不到日志就用间隔时间。
  - 关机：程序启动时上一条记录早于开机时间 = 关过机（关机时间取日志里的 13/6006/1074/109）。程序正常退出写一条 app_exit。
  - 醒来不到 1 分钟又睡（假醒）合并成一段；睡眠段里残留的窗口记录作废。不区分合盖。
  - 没有用 Windows 电源通知（WM_POWERBROADCAST）：要另开一个消息窗口，而间隔检测 + 日志已经够准、更简单。
- **首次打开**：先「风险确认」（5 条，去掉「测试版」那条），点「我了解风险并接受使用」才开始记录，点「退出软件」直接退出、
  下次还会先看到。接受的版本记在 `accepted_terms`（config.TERMS_VERSION），说明有实质改动时改版本号，会重新问。
  然后是 7 步引导：欢迎+语言 / 我所在的地区 / 记什么不记什么 / 由谁来回答 / 可选功能 / 你的记忆库 / 完成，
  有「跳过所有」「上一步」「下一步」。老用户升级上来不看引导（config 里没有 onboarded 字段 = 老用户），但要确认一次风险。
- **不自动保存**：设置页和引导里，改了没保存时「保存」按钮一直高亮，想离开（换页、切语言、翻引导）时弹出「保存 / 不保存 / 留在这里」。
  引导里有箭头提醒「填完一定要点保存设置」。
- **时区名字跟界面语言走**（方案 A）：国家名用浏览器自带的 Intl.DisplayNames，城市中文名是 ui/js/zones-zh.js 里的常用城市，
  没有的显示英文。列表只留 tzdata zone.tab 里的正式名字（去掉旧别名，免得同一城市出现两次）。
- **全屏铺满**：去掉主内容区最宽 1080 像素的限制。
- **记忆库**（library.py）：
  - 设置里显示位置，可「打开文件夹」「更改位置」。数据文件夹最外层有「记忆库说明.md」（英文界面是 MEMORY-README.md），写给 AI 看。
  - 更改位置：新位置永远是一个叫 AlwaysWithYou 的文件夹（选的文件夹里新建；选的本身就叫这个名字时直接用）。
    先停下采集和记忆库 → 复制 → 逐个核对大小 → 改指路文件 location.json（另写 location.txt 给卸载程序看）→
    只删旧位置里刚核对过的那些 → 自动重启。核对不过就删掉复制出来的、原数据不动。卸载时会把搬走的位置一起问。
  - 导出压缩包：说明 + AGENTS.md / CLAUDE.md / GEMINI.md（各家 Agent 打开文件夹时会自动读，里面指向说明）+ 记忆.md + memory.db
    + 聊天记录（勾选项，默认勾上，单独一个文件夹）+ manifest.json。不放设置、原始记录、模型。**不加密码**（用户决定）。
  - 记忆存档：archives/ 文件夹。导入 = 检查后复制进来；启用 = 先把当前的打包成「自动备份-时间.zip」放进存档，再换成选中的，自动重启。
    存档里有聊天记录就一起换，没有就保留当前的聊天。**不合并两份记忆库**（用户决定）。

### 0012 补充（2026-11-21，ChatGPT 审查后）

ChatGPT 静态审查 0.3.0 提了 7 条，核对后都属实，全部处理：
1. 存档列表的「几条记忆」直接用了压缩包里的值、没转义 → 后端按类型重新整理清单里的每个值，界面里插值的地方全部转义。
2. 记忆工具识别搜的是整个请求文本 → 只看工具名字段，必须和 4 个记忆工具完全相同，类别是命令 / 文件操作的一律拒绝
   （实测 agy：name = `mcp_awy-memory_search_memory`、kind = other）。
3. 「不含聊天记录」时 memory.db 里仍有聊天原话 → **用户决定：去掉这个选项，导出总是带全部聊天记录，导出前弹窗提醒**；
   导出的副本里所有文字（记忆、摘要、便条、写入日志、聊天）过一遍隐私打码，密码 / 密钥等换成「[已隐藏]」，再 VACUUM。
   启用存档前的自动备份不清理（要能原样换回去）。
4. 聊天原话会交给整理 AI：这是决定 0011 的设计，改的是说明文字（使用说明、设置页提示）。
5. 启用存档：校验改成按程序真正打开的方式试一遍并核对每张表的列；先把存档完整解压检查好再换；
   换的时候出错立刻用自动备份换回；万一重启后打不开，启动时自动换回（enable-pending.json）。
6. 没确认风险说明时托盘「立即整理一次」也能整理 → 整理入口本身检查，任何地方触发都不整理。
7. 整理时间清空后原始记录不再清理 → 设置不允许清空；清理改成每天一次，和整理无关。

### 0012 补充二（2026-11-21，ChatGPT 复查后）

复查提了 5 条，核对源码都属实，全部处理：
1. 启用存档换到一半退出（新库能打开、聊天只换了一部分）启动时不会换回 → `enable-pending.json` 加 `stage`：
   换之前写 `swapping`，记忆库和聊天都换完才改成 `swapped`。启动时（打开记忆库**之前**）只要还是 `swapping`，
   不管新库能不能打开都用自动备份换回（`library.recover_interrupted_enable`），并在托盘提醒。
   换回时聊天记录也原样换回（备份里没聊天就清空，不留下换进来的那份的）。立刻换回失败时如实提示「没成功、下次启动再试」，标记留着。
   旧版本写的标记没有 `stage`：沿用旧做法，只在库打不开时换回（免得把刚启用成功、还没重启的存档又换掉）。
2. 关掉「聊天内容参与整理」后，排队中的聊天仍会交给整理 AI；重新打开会补读关着那段时间的聊天 →
   关掉时（以及每次整理前发现是关着的）把还没整理的聊天 episode 标成已处理（`processed_by = chat-off`），不交给整理 AI；
   重新打开时记下 `chat_in_memory_since`，之后只从这个时间往后读。**聊天里 AI 帮你留的便条不受这个开关影响**（那是你主动说「记住」）。
3. 导出漏了人物 / 地点 / 项目的名字和别名 → 名字也打码（打码后重名就加「#编号」），含隐私的别名直接从副本里去掉。
   测试里列了每张表每个文字列「打码 / 不用打码」的归类，新加列没归类测试就会失败。
4. 存档里的聊天文件只看文件名和大小 → 启用前逐行检查（UTF-8、是一条记录、时间带时区、角色和文字类型对），看不懂的行丢掉，
   启用后提醒丢了几行。读聊天的地方（聊天页、整理、带上下文）也统一用 `chat.parse_record`，坏行跳过；
   读聊天出错也不耽误电脑活动的整理（以前坏文件会让整理一直失败）。
5. 保留天数不检查范围，太大会让调度线程退出；**0 或负数还会把今天的原始记录删掉** → 设置接口只收 1~3650 的整数；
   读配置文件和清理时也整理到这个范围；每日清理放进异常保护里，出什么错都只记日志。

  所有副本共用这些变量，所以一起漂移、不用逐个更新。动效「关闭」或系统「减少动态效果」时不动。

## 0014 手机端 AwyRead：使用时长、后台读取、同一个 Wi-Fi 里传给电脑（2026-11-22）
